Step 01 · Method

Map the processes As Is and To Be

Map how the company works today (As Is) and how it should work after the project (To Be).

Focus on one thing, with one ID

Pick the main thing you need to follow from start to finish and give it an ID. The ID is the point of contact between Notion pages along the process.

Define which bases feed the others
Where possible, create relations between Notion pages, so columns fill in automatically and the information stays the same along the process
Not every base will be connected, but most can be
IDs have different uses

Some IDs are a permanent identity, like a company’s tax ID or a person’s work email. Others work like an RFID tag: a temporary code that ties the steps of one process together.

In the client build, a registration code is born with each opportunity in the Sales Funnel. It brings the client’s registration answers into that same opportunity and tells n8n which context to process. Once the company and its people are identified, relations use the Notion page links and the code is no longer needed. Registration code → Opportunity → Company and People → Project.
Draw the flow
List the document that marks each stage (presentation, proposal, contract, invoice). They become your triggers later
Mark the inputs and outputs from one Notion page to another
Draw it on paper: how things move from one flow to the next, and where each step is manual or automated
You end up with two views of the process: the process as written, and the flow drawing. Both help later, when you read the n8n workflows. Workflows often come split into pieces, not as one full process.

Step 03 · Method

Decide what stays manual and what gets automated

Go through each step of the To Be map and mark it human or automated.

Human→Judgment: verify a lead, qualify it, review a draft, attach a document, mark a payment
Automated→Execution: create drafts, send emails, save files, schedule follow-ups, move records
Our choice: simple automations, humans in the loop
We built simple automations with manual steps along the way, so the founders are always part of the process. They wanted it this way
It also saves money: we didn’t need many agents, which consume a lot of tokens

Step 04 · Method

Link controls to actions

Controls are the signals in Notion: a status change, a checkbox, a new file URL in a field. Each control triggers one or more actions.

Client examples
Checkbox “Verified”→First-contact email draft created in the owner’s Gmail
Checkbox “Hot lead”→Lead and its data copied to the Sales Funnel
New sales document→Status updated, document emailed to the client, follow-up task created
Status “Closed”→Project created, Drive folder created, all sales docs saved at once
New project document→Status updated, document emailed to the client, follow-up task created, file saved to Drive
Checkbox “Send Feedback”→Feedback form sent to the client
Status “Upsell”→New funnel entry and upsell email draft

The client’s workflows
Workflow · Weekly verification reminderEvery Monday morning, finds the leads nobody has verified yet and emails the list to the team.
Workflows · Verified lead → first-contact emailWhen “Verified” is ticked, creates the first-contact email draft to the lead. One workflow per lead source.
Workflows · Hot lead → Sales FunnelWhen a lead replies and the team ticks “Hot lead”, copies the lead and its data from the research results into the Sales Funnel and assigns the right person. One workflow per lead source.
Workflow · Sales Funnel documentsEach of the 5 sales documents fires 3 actions when attached: status update, email to the client with the file, and a follow-up task for the team. A URL check makes sure each file fires only once.
Workflow · Closed → Project + DriveWhen the signed contract closes the deal, creates the project in Notion and a Drive folder with subfolders, and saves all sales documents at once. Emails the team if a copy fails.
Workflow · Project documentsEach project document (Script, Onboarding, Invoice 1, Invoice 2) fires the same 3 actions, plus saving the file to Drive.
Workflow · Feedback formOnce the final invoice is paid, the team ticks “Send Feedback” and the client gets the satisfaction form link.
Workflow · UpsellWhen a project moves to “Upsell”, creates a new entry in the Sales Funnel and an email draft for the team to adjust.
Step 07 · Method

Refine the logic and add guardrails

Review each workflow and adjust its logic through Claude. Discuss the guardrails you think are needed and have Claude apply the changes directly in the workflows.

Client guardrails
Dedup check→n8n listens to “page updated”. It stores each document URL and only fires when the URL is new, so one edit never sends several emails
Save after signing→Sales docs go to Drive only when the deal closes. Before that, the lead may still drop
Draft first→First contact is a Gmail draft the team reviews, not a direct send
n8n errors we hit, so you don’t
01Reprocessing loop: the same email sent more than once
02Trigger polling at a fixed hour instead of every minute
03Wrong place to connect the MCP server in Claude.ai
04Missing or misconfigured filter runs the flow on the wrong records
05Gmail credential can’t be chosen dynamically: it’s fixed per node
06n8n Community has no user-level access control
07Execution shows success, but nothing actually happens
08Notion relation fields only bring the related page ID, not its data
Full symptoms, causes and fixes are in the n8n errors guide.
